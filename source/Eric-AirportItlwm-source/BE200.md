# BE200 development notes

This branch adds Intel Wi-Fi 7 (BE family) support to the native Tahoe/Sequoia
`AirportItlwm` from [laobamac/itlwm](https://github.com/laobamac/itlwm). Linux
iwlwifi (`mvm`, `mld`) and mac80211 are the behavioural reference for every
firmware command and protocol step; OpenBSD `if_iwx`/net80211 is the code base
it is written in.

## Hardware and firmware selection

PCI IDs `272b` (BE200/BE202, Killer BE1750 x/w, discrete GL transport) and
`a840`, `7740`, `4d40` (BE201, Killer BE1750 i/s, integrated BZ transport) are
matched. MAC/RF revision, stepping and CDB generate the firmware prefix as in
Linux v6.12 `iwl_pci_find_dev_info()`; a candidate needs both its uCode and its
paired PNVM.

| Hardware prefix | Adapted APIs | Default |
|---|---|---|
| `iwlwifi-gl-c0-fm-c0` | 92, 86 | 92 |
| `iwlwifi-bz-b0-fm-c0` | 92 | 92 |
| `iwlwifi-bz-b0-gf-a0` | 92 | 92 |

The highest adapted API is tried first; a candidate that fails to load moves to
the next one for the same prefix (`itlwm_gl_api=86` is a debugging cap). Command wire formats follow the
firmware's command-version TLV table.

HE/EHT is on by default (`itlwm_he=0` turns it off; 320 MHz needs UHB and the matching
firmware APIs). The country comes from the firmware's location-aware regulatory logic
(LAR) and the networks around, as on Linux.

## Connection pipeline

Each stage lists where it lives and its Linux reference. "Hardware" means
observed on a BE200 with real traffic; everything else is source-level only.

| Stage | Code | Linux reference | Status |
|---|---|---|---|
| Scan: PSC/RNR-hinted 6 GHz channels, short SSID, dwell | `iwx_umac_scan_v17`, `ieee80211_collect_scan_rnr` | `mld/scan.c` | Hardware (6 GHz networks listed) |
| Results to WCL, BSS selection | `publishWCLBeacon`, `postWCLScanResult` | (Apple WCL) | Hardware |
| Join request, AKM selection | `startWCLJoin`, `ieee80211_choose_rsnparams` | `mac80211/mlme.c` | Hardware (WPA2, WPA3) |
| SAE (H2E and hunting-and-pecking) | `ieee80211_sae.c`, `ieee80211_auth_sae` | `hostapd` SAE | Hardware: 6 GHz SAE/H2E |
| Association request: HE/EHT capabilities, Basic MLE | `ieee80211_get_assoc_req`, `ieee80211_add_mld_assoc_req` | `mac80211/mlme.c` | Hardware: single link; a WPA3 router with MLO enabled joins |
| Affiliated link discovery: ML probe at join, per-STA profile expansion, link usability | `iwx_fill_probe_req`, `ieee80211_recv_ml_probe_resp`, `ieee80211_mld_discover_links` | `wpa_supplicant_connect_ml_missing()`, `cfg80211_parse_ml_elem_sta_data()`, `wpa_bss_get_usable_links()` | Unverified |
| Association response, accepted links | `ieee80211_mld_assoc_response_links` | `mac80211/mlme.c` | Unverified |
| Firmware MAC/LINK/STA setup per link | `iwx_mld_auth`, `iwx_mld_run`, `iwx_mld_add_sta_cmd` | `mld/iface.c`, `mld/link.c`, `mld/sta.c` | Hardware for one link |
| Keys (PTK, GTK, IGTK, BIGTK) | `iwx_mld_set_key` | `mld/key.c` | Hardware: PTK/GTK |
| Rate control, A-MPDU, A-MSDU | `iwx_rs_init`, `iwx_rs_update`, `iwx_tx_amsdu` | `mld/tlc.c`, `pcie/tx-gen2.c` | Hardware: 6 GHz 320 MHz, 2882 Mbit/s link, 2.55 Gbit/s TX / 1.84 Gbit/s RX |
| Active links, eMLSR, TTLM | `iwx_mld_update_active_links`, `iwx_mld_select_links`, `iwx_mld_tpt_task`, `iwx_ttlm_apply` | `mld/mlo.c`, `mac80211/mlme.c` | Link pairing not yet seen in logs |
| Reporting to macOS (channel, width, PHY, rates) | `getWCL_BSS_INFO`, `copyWCLExtendedBss` | (Apple WCL) | Hardware; the menu shows 320 MHz as 20 MHz, a limit of Apple's channel descriptor |

A join to an AP MLD probes the target BSSID with a Multi-Link probe request, so the other links are known even
after the node table was flushed; a link is used when it shares the chosen AKM and pairwise cipher, has MFP and
matches the MLD/EML capabilities. All accepted links are configured, and the joined link is active first.

The BE200 has one radio: two links are active only as an EMLSR pair, which carries traffic on one link at a
time, so rates do not add up. The firmware never recommends EMLSR, so the driver chooses as
`iwl_mld_select_links()` does: EMLSR stays blocked until traffic reaches 400 MPDUs in 5 s, links are graded by RSSI,
channel load and punctured share, and the best pair on different bands is entered when the AP offers EMLSR;
otherwise the best single link is used. EMLSR is left on low RSSI, low load, a firmware request or a failed
transition, and not retried for 30 s (300/600 s on repeats). A choice the firmware refuses is rolled back; it does
not drop the association. STR is not implemented. EAPOL, management and data use the primary link; macOS keeps the
BSSID of the join and is told the channel, width, signal and quality of the active link. The kernel log lists every
link and every active-link change, and the collector copies them into `negotiated-links.txt`.

Not done, all unverified on hardware: leaving EMLSR for low link usage (frames are not attributed to a link),
iwlmld's duplicate-beacon and PSD/EIRP RSSI correction (a fixed 4 dB is used on 6 GHz), and rates and MCS shown to
macOS still come from the first link.

## AirDrop (AWDL)

`-itlawdl` creates `awdl0` and hands it to macOS's own AWDL stack (Tahoe 568-slot and Sequoia 563-slot
`IO80211AWDLProtocol` tables; the driver checks anchor slots at start and runs as plain Wi-Fi when they differ,
`AWDLBuildCheck`). It also turns on the single `-itlawdl*` flags that used to be listed one by one. Every card but
the AX411 has one radio, so the listener is a second context the firmware time-shares with the station.

- **Legacy firmware (AX200/201/210/211):** LISTENER MAC on the spare PHY context with its own binding, a
  general-purpose station and a management queue (`iwx_legacy_listener_setup`), as ForbiddenItlwm runs it on the
  AX211. VHT80 on 149 when 149-161 are all usable, and a data-rate ladder from 54 Mbit/s. `-itlawdllegacyba` adds a
  firmware receive Block Ack session for the peer (promiscuous receive stays off while the peer station exists).
- **MLD firmware (BE):** MAC_CONFIG, LINK_CONFIG, PHY_CONTEXT, STA_CONFIG and a queue, as iwlmld builds a P2P client
  (`iwx_mld_listener_setup`). The link stays out of every band the station uses (the LMAC asserted on two 5 GHz
  channels) and moves before a join that would put the station in its band (`iwx_awdl_listener_refit`). One peer
  station with separate data and management queues, firmware RX BAID reordering, TX A-MPDU left to the firmware's TLC
  (API v4 on the bundled FW92, v6 when advertised), TX completion from the FW92 `BA_NOTIF` v5 layout.
- **IWM firmware (7000, 8000 and 9000 series):** a third PHY context, listener MAC and binding, DQA P2P queues, one
  peer station and software CCMP (`iwm_awdl_*`). Firmware with multi-queue RX also uses RX BA reordering. Firmware
  with host-managed quotas disables power saving while the listener is bound and restores it on unbind.
- **iwn firmware with PAN and P2P:** a second DVM RXON context on the station's channel 6. PAN uses command
  queue 9, its own TX FIFO and a separate broadcast station. The driver waits for firmware deactivation
  before reusing the context. Unicast ACK and bidirectional AirDrop await hardware verification.

AirDrop discovery and Sidecar traffic registration are tracked apart; while either is active the BE listener gets
`LOW_LATENCY_CMD` (plus the MLD low-latency power table in client mode). `setLLW_PARAMS` maps Apple's enable byte
(`+0x0b`, read from Tahoe 25E246) to its own reason bit. `llw0` is created by `COMPANION_SKYWALK_IF_CREATE` (role 2,
interface 9) and carries RFC 1042 frames on separate TID 6 queues (peer unicast, listener multicast); AWDL itself stays
on TID 0. `setPEER_CACHE_CONTROL` is answered with event 51 and the status of unicast action frames with event 69, as
Broadcom's firmware does.

The listening channel is 149, then 44, then 6, at 20 MHz (80 MHz on 149 for legacy firmware), only where the
regulatory map allows transmitting; a passive channel counts once an AP was heard beaconing on it
(`ic_beacon_hint`). The country comes from the firmware's regulatory notices, which the driver also answers while
associated.

Automatic MI honors the sparse OOB bitmap: slot = `min(15, (AWSeq % (count * (step + 1))) / (step + 1))`, sent only
when `bitmap & (1U << slot)` is set (Tahoe 25G229).

Status: Tahoe and Sequoia build. AirDrop is not confirmed on any card.

## Diagnostics

The PCI device carries what a community report needs to identify a failure:

- `AirportItlwm-FirmwareError*` (`Count`, `Lmac`, `Um`, `Driver`, and `First*` for the first assert): the error tables
  of the firmware asserts.
- `AirportItlwm-TxTrace` / `TxTraceFirst`, `TxQueueMap`, `TLCConfigRequest`: the last 48 TX commands, the TID-to-queue
  map and the rate-scaling request, saved with an assert.
- `AirportItlwm-RxFragments`, `RxBadRbid`: receive-ring anomalies.
- `AirportItlwm-Diagnostic00`-`31`, `DiagnosticSequence`: a ring of driver events (recovery, init/stop, command and
  state errors).
- `AirportItlwm-FirmwarePrefix`, `FirmwareAPI`, `PNVMName`, `FirmwareCandidateIndex`: the selected firmware.
- `AWDL*`: listener stage and result, activation state, peer and Block Ack counters.

`scripts/Collect-EricWirelessDiagnostics.command` records these with the kernel and airportd logs during one attempt.

## Build

The workflow builds Tahoe and Sequoia x86_64 kexts against MacKernelSDK
`3f750085caa17ec3a7880f11c11bf4f48cd6a164`. The pinned SDK predates the public
MSI-X declaration, so `scripts/prepare_tahoe_sdk.py` checks the header hash and
exposes Apple's `IOPCIDevice::configureInterrupts` in reserved slot 3
([Apple's header](https://github.com/apple-oss-distributions/IOPCIFamily/blob/main/IOKit/pci/IOPCIDevice.h)).

```sh
python3 scripts/prepare_tahoe_sdk.py
xcodebuild -project itlwm.xcodeproj -scheme AirportItlwm-Tahoe \
  -configuration Debug ARCHS=x86_64 CODE_SIGNING_ALLOWED=NO build
```

A build is not a hardware result.
